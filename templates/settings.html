Configuration Guide

Telegram 通知

  1. 在 Telegram 搜 @BotFather，发 /newbot 按提示建机器人
  2. 把拿到的 Bot Token 填进本页「Telegram 通知 → Bot Token」
  3. 拿 Chat ID：给机器人发一条消息，再访问 https://api.telegram.org/bot<TOKEN>/getUpdates，其中的 chat.id 就是
  4. 填好后点 Test Connection 验证
  5. 勾上 Enable Telegram notifications —— 不勾就完全不发（发通知前会检查这个开关）

两类通知分别控制，互不影响：

  • 告警（Alert）：由「告警最低推送级别」决定。选 error = 只推 critical + error， warning 及以下不推但仍会入库。单条过滤规则勾了「任意级别」则绕过该门限。
  • AI 分析汇总：由「AI 分析汇总推送状态」的 4 个勾选框决定，默认只勾 critical。 勾得越少越安静；一个都不勾 = 不推。「AI 汇总冷却」限制同类汇总的推送间隔。

AI 分析

  1. AI Protocol：OpenAI-compatible（vLLM / SGLang / Ollama 的 /v1） 或 Ollama（原生 API）
  2. AI Endpoint：形如 http://192.168.50.23:8000/v1（可省略 /v1，会自动补全）
  3. Model：点 Refresh 从 /v1/models 拉取后选择
  4. 处理建议的主机：由模型自己匹配——提示词要求每条"发现的问题/处理建议"都以 [主机名/IP] 开头，程序不再猜主机。
  5. AI Sample Limit per Batch（通用设置里）：真正送进提示词的行数，按级别从严重到轻微取前 N 行。

⚠️ AI Endpoint 留空即可——留空时会用部署时 env 里的 AI_BASE_URL。千万不要在留空状态下手动填 http://localhost:11434：本容器里没有本地 Ollama，会让全部分析报 Connection refused（线上踩过这个坑）。

AI 判定口径（critical / warning / healthy）

  • 纯模型判定（与 python-legacy 一致）：模型的 overall_status 判什么就是什么，程序只做同义词归一（critical/error → critical，warning/notice → warning，info/healthy → healthy，其余 → other），不做任何修正。
  • 提示词可选：默认简单版，或「按 Qwen3.5-9B 调校」的 few-shot 前缀缓存版（见「建议使用模型」下拉框）；日志按级别排序、带 [SEVERITY] 前缀原样交给模型。模型返回的 issues/建议原样保留（不去重、不封顶 critical_count）。
  • 过小的模型（如 3B）容易走 healthy/critical 两极、判不准 warning——这是模型能力边界，不属于程序修正范围；默认的 Qwen3.5-9B 已明显改善。

存储与保留（冷热分层）

  • Log Retention (days)：日志 和 AI 分析历史的保留天数（两者共用），到期自动清理。
  • Redis Hot Data Window (days)：超过此时长的日志/分析/告警哈希会归档到 SQLite（冷存储）， Redis 只留索引。设为 0 表示关闭归档。与内存强相关：哈希是 Redis 内存大头，天数越大 Redis 保留的哈希越多、内存越高；调小省内存，代价是冷数据回读 SQLite 稍慢。
  • Alert Retention (days)：告警记录的保留天数。
  • Clear All Data / Purge Expired Data：清理会同时作用于 Redis 与 SQLite 两个库，且不可撤销。

各项改动何时生效

  • 约 10 秒内：自动分析开关、告警最低推送级别、分析间隔、Telegram 通知开关（Enable）
  • 下一次巡检：巡检间隔 / 积压阈值 / 告警冷却 / 巡检日报
  • 下一轮分析：每轮取多少条日志、送模型多少条、AI 汇总推送状态
  • 下一次归档任务（≤5 分钟）：Redis 热数据窗口
  • 对之后新写入的数据生效：日志保留期、告警保留期
  • 需要重启容器：AI Endpoint / AI Protocol（启动时读取）；Telegram 凭据内部有 5 分钟缓存

Rsyslog 接入

在被采集的机器上加一行（本机监听 UDP 514 / TCP 515）：

# /etc/rsyslog.d/99-logaimonitor.conf
*.* @192.168.50.6:514     # UDP
# 或
*.* @@192.168.50.6:515    # TCP（可靠传输，推荐）

改完执行 systemctl restart rsyslog。 若 rsyslog 跑在容器里，目标地址写宿主 IP 或 host.docker.internal。
